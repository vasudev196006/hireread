**The one-sentence pitch you are building toward:**
"HireReady replaces unverifiable resume keywords with a transparent, deterministic, explainable match score — so both recruiters and candidates can see *exactly* why a score is what it is."

**The centerpiece feature (do not ship without this working perfectly):**
A score breakdown view (radar chart or stacked bar) that decomposes any match score into its 6 weighted components (Required Skills, Preferred Skills, Experience, Education, Certifications, Projects) from Section 4. ## 1. System Overview & Core Philosophy

SkillBridge (HireReady) eliminates credential mismatch and noisy resume filtering by replacing unverified keywords with **verifiable competency matching**, **real-time job market analytics**, and **deterministic candidate scoring**.

### Core Pillars
1. **Recruiter Platform**: Multi-step job authoring, skill weighting (Required vs. Preferred), deterministic candidate ranking, and hiring pipeline analytics.
2. **Learner Platform**: Live competency gap analysis against target industry roles, personalized upskilling roadmaps, and verifiable micro-credentials.
3. **Workforce Intelligence**: Real-time job market aggregation (Adzuna API + cached fallbacks), skill supply/demand heatmaps, and platform-wide verification audits.

## 3. Database Schema (`PostgreSQL / Supabase`)

```sql
-- 1. EXTENSIONS
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";

-- 2. USERS TABLE
CREATE TABLE IF NOT EXISTS public.users (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  name TEXT NOT NULL,
  email TEXT UNIQUE NOT NULL,
  role TEXT NOT NULL CHECK (role IN ('recruiter', 'candidate', 'admin')),
  avatar_url TEXT,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 3. CANDIDATE PROFILES
CREATE TABLE IF NOT EXISTS public.candidate_profiles (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  user_id UUID REFERENCES public.users(id) ON DELETE CASCADE UNIQUE,
  headline TEXT NOT NULL,
  location TEXT NOT NULL,
  experience_years NUMERIC(4, 1) NOT NULL DEFAULT 0,
  education TEXT NOT NULL CHECK (education IN ('any', 'diploma', 'bachelors', 'masters', 'phd')),
  bio TEXT,
  github_url TEXT,
  linkedin_url TEXT,
  work_preference TEXT CHECK (work_preference IN ('remote', 'hybrid', 'onsite')),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 4. SKILLS MASTER LIST
CREATE TABLE IF NOT EXISTS public.skills (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  name TEXT NOT NULL UNIQUE,
  category TEXT NOT NULL
);

-- 5. CANDIDATE SKILLS (WITH VERIFICATION STATUS)
CREATE TABLE IF NOT EXISTS public.candidate_skills (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  candidate_id UUID REFERENCES public.candidate_profiles(id) ON DELETE CASCADE,
  skill_id UUID REFERENCES public.skills(id) ON DELETE CASCADE,
  proficiency TEXT NOT NULL CHECK (proficiency IN ('beginner', 'intermediate', 'advanced', 'expert')),
  years_experience NUMERIC(4, 1) NOT NULL DEFAULT 0,
  verified BOOLEAN DEFAULT FALSE,
  verification_score NUMERIC(5, 2) DEFAULT 0.0,
  verified_at TIMESTAMP WITH TIME ZONE,
  UNIQUE (candidate_id, skill_id)
);

-- 6. JOBS
CREATE TABLE IF NOT EXISTS public.jobs (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  recruiter_id UUID REFERENCES public.users(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  company TEXT NOT NULL,
  description TEXT NOT NULL,
  location TEXT NOT NULL,
  work_mode TEXT NOT NULL CHECK (work_mode IN ('remote', 'hybrid', 'onsite')),
  employment_type TEXT NOT NULL CHECK (employment_type IN ('full-time', 'part-time', 'internship', 'contract')),
  min_experience NUMERIC(4, 1) NOT NULL DEFAULT 0,
  max_experience NUMERIC(4, 1) NOT NULL DEFAULT 0,
  education TEXT NOT NULL CHECK (education IN ('any', 'diploma', 'bachelors', 'masters', 'phd')),
  salary_min NUMERIC(12, 2) NOT NULL DEFAULT 0,
  salary_max NUMERIC(12, 2) NOT NULL DEFAULT 0,
  currency TEXT DEFAULT 'INR',
  status TEXT DEFAULT 'active' CHECK (status IN ('active', 'closed', 'draft')),
  created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- 7. JOB SKILLS (REQUIRED VS PREFERRED WEIGHTING)
CREATE TABLE IF NOT EXISTS public.job_skills (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  job_id UUID REFERENCES public.jobs(id) ON DELETE CASCADE,
  skill_id UUID REFERENCES public.skills(id) ON DELETE CASCADE,
  required BOOLEAN DEFAULT TRUE,
  importance TEXT NOT NULL CHECK (importance IN ('required', 'preferred')),
  UNIQUE (job_id, skill_id)
);

-- 8. VERIFIABLE CERTIFICATIONS & CREDENTIALS
CREATE TABLE IF NOT EXISTS public.certifications (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  candidate_id UUID REFERENCES public.candidate_profiles(id) ON DELETE CASCADE,
  name TEXT NOT NULL,
  issuer TEXT NOT NULL,
  credential_id TEXT NOT NULL,
  verification_url TEXT,
  verification_hash TEXT,
  issue_date DATE NOT NULL,
  verified BOOLEAN DEFAULT TRUE
);

-- 9. CANDIDATE EVIDENCE / PROJECTS
CREATE TABLE IF NOT EXISTS public.projects (
  id UUID PRIMARY KEY DEFAULT uuid_generate_v4(),
  candidate_id UUID REFERENCES public.candidate_profiles(id) ON DELETE CASCADE,
  title TEXT NOT NULL,
  description TEXT NOT NULL,
  github_url TEXT,
  live_url TEXT,
  technologies TEXT[] DEFAULT '{}'
);
```

## 4. Deterministic Transparent Matching Engine

The match score between a candidate $C$ and job $J$ is calculated out of 100 points:

$$\text{Match Score} = S_{\text{req}} + S_{\text{pref}} + S_{\text{exp}} + S_{\text{edu}} + S_{\text{cert}} + S_{\text{proj}}$$

### Weighting Breakdown:
| Factor | Weight | Formula / Rules |
| :--- | :--- | :--- |
| **Required Skills ($S_{\text{req}}$)** | **50%** | $\min\left(50, \text{round}\left(\frac{\sum \text{Matched Weight}}{\text{Total Required}} \times 50\right)\right)$. Base match = 1.0; Verified = +0.05; Expert = +0.05. |
| **Preferred Skills ($S_{\text{pref}}$)** | **15%** | $\text{round}\left(\frac{\text{Matched Count}}{\text{Total Preferred}} \times 15\right)$. If no preferred skills specified, award full 15 pts. |
| **Experience ($S_{\text{exp}}$)** | **15%** | $15$ pts if $\text{Exp}_C \ge \text{Exp}_{\min}$. Else $\text{round}\left(\frac{\text{Exp}_C}{\text{Exp}_{\min}} \times 15\right)$. |
| **Education ($S_{\text{edu}}$)** | **5%** | $5$ pts if Rank($\text{Edu}_C$) $\ge$ Rank($\text{Edu}_J$). Ranked: `any (0) < diploma (1) < bachelors (2) < masters (3) < phd (4)`. |
| **Certifications ($S_{\text{cert}}$)** | **5%** | $5$ pts if candidate holds at least 1 verified certificate matching job tech stack, else $2$ pts for general verified certs. |
| **Evidence / Projects ($S_{\text{proj}}$)** | **10%** | Awarded based on GitHub projects matching required stack tags (up to 10 pts). |

## 5. Backend Server API (`server/index.js`)

- **Port**: `3001` (CORS enabled for `http://localhost:5173`)
- **Endpoints**:
  1. `GET /api/health`: Returns server status, uptime, and Adzuna API availability.
  2. `GET /api/market/jobs?what={query}&where={location}&country={code}`:
     - Connects to Adzuna API (`https://api.adzuna.com/v1/api/jobs/{country}/search/1`).
     - Extracts technical skills using NLP keyword regex parser.
     - Gracefully falls back to local high-fidelity dataset if API keys are not provided.
     - Computes real-time skill demand frequencies.
  3. `GET /api/market/analytics`:
     - Aggregates market demand curves across 1,400+ jobs.
     - Computes talent supply vs. demand gap metrics for top tech skills (Python, SQL, React, Docker, AWS, etc.).

## 10. Seed Data Strategy

Nothing on screen matters if the data behind it looks fake. Generate seed data **before** building any UI (Hour 0–1), not as an afterthought.

**Minimum viable dataset:**
- **~15 jobs** across 4–5 realistic roles (e.g., Frontend Engineer, Backend Engineer, Data Analyst, DevOps Engineer, Full-Stack Engineer), each with a real-looking mix of 4–8 required/preferred skills from a shared skill pool.
- **~40 candidates** with varied experience levels, some fully matching a role, some partial matches, some poor matches — you want the ranked list to show visible score spread (not everyone scoring 95).
- A **shared skills taxonomy** of ~30–40 real technical skill names (React, Node.js, PostgreSQL, Docker, AWS, Python, TypeScript, Kubernetes, GraphQL, etc.) with categories, so skill matching logic has something consistent to key off.
- For each candidate: a mix of `verified: true/false` skills, 0–2 certifications (some verified), and 1–2 GitHub-style projects with a `technologies` array — these feed the Certifications and Projects scoring factors directly, so make sure the seed data actually varies them enough to produce different scores.

**How to generate it fast:**
- A single Node/JS seed script using `@faker-js/faker` for names/bios/locations, with skills, certs, and projects sampled (not fully random) from curated arrays so results stay realistic and reproducible.
- Write the script to output directly to your DB (or a static JSON file if you're skipping a database for speed — see Section 13) so it can be re-run instantly if you tweak the schema.
- Keep the seed data **deterministic** (fixed seed/array order) so your rehearsed demo script always surfaces the same top-ranked candidate — you do not want random data reshuffling your "golden path" candidate the night before judging.

## 11. Demo Script (Golden Path)

Rehearse this exact ~3-minute path. Every feature you build should serve one of these beats — anything that isn't on this path is lower priority.

1. **Hook (15s):** "Hiring today runs on unverifiable resume keywords. We built a deterministic, explainable match score instead."
2. **Recruiter side (60s):** Open a pre-existing job (or create one live) → weight a couple of skills as Required vs. Preferred → land on the ranked candidate list → point out the visible score spread.
3. **The centerpiece (45s):** Click the top-ranked candidate → the score breakdown view appears → narrate 2–3 of the six factors out loud (e.g., "50 points for required skills, but only 42 because two are unverified — see this badge") → this is the moment judges should remember.
4. **Learner side (45s):** Switch role/context to that same candidate as a learner → show the target-role gap radar → "same scoring engine, same transparency, now pointed at the learner."
5. **The extra (30s):** Land on the credential verification page (or the market heatmap) → "and every credential is independently verifiable via this hash" (or "and this scoring is grounded in real market demand data, not guesses").
6. **Close (15s):** Restate the one-sentence pitch from Section 0.

Do not improvise a different path live — click exactly this sequence every rehearsal so muscle memory carries you through nerves.

## 12. Explicit Scope Cuts for Hackathon (Do Not Build These)

These are intentionally out of scope for a 24-hour build. Building any of them is time stolen from Section 9's phases.

- **Real authentication** — a role switcher (`recruiter` / `candidate` / `admin`) in global state is sufficient. No signup, login, sessions, or JWTs.
- **Real Row Level Security policies** — despite the schema/architecture diagram referencing RLS, do not write `CREATE POLICY` statements. This is a demo, not a production system.
- **Live third-party API calls during judging** — pre-fetch Adzuna data once, cache it as static JSON, serve that. A live API call timing out mid-demo is one of the most common hackathon failure modes.
- **A full applications/hiring pipeline** — there is no `applications` table in Section 3 and none is needed. If `/employer-analytics` needs to reference pipeline stages, fake a static "Applied → Interviewing → Offer" progress indicator on one candidate rather than building real state transitions.
- **`POST /api/skills/extract` as real NLP** — hardcode a keyword-match array against known skill names. Nobody is judging your regex.
- **File/resume upload and storage** — `avatar_url`/GitHub links as plain text fields are enough; no Supabase Storage integration.
- **A built-out admin dashboard** — 2–3 stat cards pulling numbers you already have elsewhere is enough; no real audit logging.
- **Pagination on `/api/market/jobs` or the matches feed** — fine to render the full seed set for a demo-sized dataset.

## 13. Replit-Specific Deployment Notes

- **Secrets**: Store Adzuna and Supabase keys in Replit's Secrets panel, not in `.env` files committed to the repo.
- **Database options, fastest to slowest to set up**: (1) skip a database entirely and run the scoring engine client-side against a static seed JSON — fastest, and defensible for a 24hr demo since Section 4's formula is pure computation; (2) a hosted Supabase project (matches Section 3's schema exactly, use the Supabase JS client directly from the frontend to avoid needing Express at all for reads); (3) Express + Postgres per the original architecture, only if the team has bandwidth for the extra layer.
- **Server necessity check**: If you go client-side-only for scoring and use Supabase's client SDK directly, you may not need the Express server from Section 5 at all except for the Adzuna proxy — consider cutting it entirely and fetching the cached market JSON as a static asset instead.
- **CORS**: If you do keep the Express server, update the CORS origin from `http://localhost:5173` to your actual Replit dev/deployment URL, or the deployed demo will silently fail on data fetches.
- **Always-on for judging**: Confirm the Repl is reachable (via Replit's deployment/webview link, not just the dev preview) well before your judging slot — do not rely on the dev server surviving unattended.
- **Single-repo simplicity**: Keep frontend and backend (if kept) in one Repl running both processes (e.g., via a `concurrently` script) rather than splitting across multiple Repls — one fewer moving part to break during a demo.
